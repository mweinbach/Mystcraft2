# Original industrial asset layer

The visual layer generated by `tools/visual_assets.py` is new work under the
module's MIT license. Its PNG pixels and JSON geometry are authored by the script;
no upstream ICBM art, models, textures, language files or sounds were copied.
The texture writer uses Python's standard library and deterministic pixel rules.
It does not fetch or embed external artwork.

The palette uses dark gunmetal, silver framing, gold hazard markings and teal
instrument displays. Ten original industrial surface textures include a four-frame
instrument panel and a four-frame exhaust glow. `tools/payload_visuals.py` is the
only payload-identity table. It paints 23 glyph labels, chooses one of six missile
bodies, and writes `payload_visuals.json` for the client blast color, shape, particle,
and vanilla sound. Nuclear, chemical, incendiary, and redmatter missiles do not share
a body. Label faces use an explicit full-texture uv so a short sleeve still shows the
glyph. Redmatter core and disc textures, and the radioactive top mark, are original
pixels on the same ordinary layers.
New geometry covers missiles, grenade/bomblet forms,
launcher tiers and components, radar, SAM, EMP hardware and major handheld tools.
Physical projectile models retain the renderer's +Y flight axis.
The 128×128 mod icon `assets/icbm_port/icon.png` (referenced by `fabric.mod.json`)
is drawn by `icon()` in the same script: an upright missile with a gold hazard
band over a hazard-striped gunmetal plate, using only this palette.

Radar and SAM block models intentionally provide only the static base and mount;
the client block-entity renderer supplies their moving upper hardware. Separate
inventory model parents contain complete silhouettes. Loaded/unloaded variants and directional semantics remain intact. Tiered bases
use vertical +Y rail tubes with no UP rotation, matching their normal UP placement;
prototype/cruise tubes remain native NORTH with their directional rotations.

`generate_resources.py` applies this layer last so resource regeneration does not
restore earlier placeholder models. It leaves gameplay recipes and material tags
unchanged. `validate_resources.py` checks local PNG signatures/dimensions and
animation-strip metadata in addition to existing resource references.

The final icon pass adds 14 original transparent RGBA component sprites and 23
payload-marked three-dimensional cart inventory models. No item uses a vanilla
item-sprite substitute. Some building blocks and cargo materials still reference
vanilla block textures by design. This work is a cohesive original
interpretation, not a recreation of upstream artwork or a claim that every item
has finished bespoke art. Selected models, held launcher transforms and moving-head alignment were reviewed
in the full Tekxit client alongside the renderer changes.

## Flat explosive faces (after alpha.4)

The 14×16×14 explosive casing model, whose painted bevels pretended to be a
3D frame on what the game treats as a full opaque cube, is replaced by a plain
`minecraft:block/cube_bottom_top` model per payload. It follows a TNT-like
layout: a side, a top and a bottom texture. `paint_explosive_side`,
`paint_explosive_top` and `explosive_bottom_pixels` in `tools/payload_visuals.py`
paint them from flat colour rules. The side has casing bands, payload-coloured
charge sticks and a dark label band carrying the family glyph. The top shows
four stick ends around a detonator. The bottom is shared by all payloads. No
shading gradients or perspective are drawn. Item models still parent the block
model, so the icons match. The pixels are original, MIT-licensed work generated
by the script. Neither the upstream ICBM textures nor its models were consulted
or derived from. `tools/check_payload_visuals.py` enforces the flat rules and
face uniqueness. `tools/render_contact_sheet.py` rasterizes the faces and
isometric icons, without a game client, into the before/after sheets
in `docs/images/`.
