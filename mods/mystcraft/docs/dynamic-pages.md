# Registry-backed symbol acquisition

Reference: official Mystcraft-Legacy commit `9bc8ddc061845df0cd5ea47f4fdef773cff786ae`, especially `ModSymbols.generateBiomeSymbols`, `ModSymbolsModifiers`, `ModSymbolsFluids`, `SymbolManager`, `ItemBoosterPack`, `SymbolBiome` and `SymbolBlock` (LGPL-3.0).

`DynamicSymbolPages.choices(RegistryAccess)` builds a fresh immutable view of the current world's biome registry and eligible physical source fluids. No world registry or former client's biome list is cached globally. The client supplies its current level registry through a supplier; disconnected lookups return no dynamic choices. Metadata/payload accessors copy their returned values.

Biome pages use `mystcraft:biome/<namespace>/<path>`. Their card rank is 2. The End biome retains the original unranked exception: it is discoverable in creative mode but excluded from random survival acquisition. Names use biome translation keys, and their four-word poem is Nature / Nurture / Encourage / native biome ID. The final word deliberately replaces the old numeric-registry-derived word with a stable modern registry name; the port never guesses a legacy numeric ID from current registry order.

Additional liquid pages use `mystcraft:fluid/<namespace>/<path>` and retain `Fluid` as the native fluid ID plus the exact source `BlockState`, `Sea` and `FluidMaterial` tags. Flowing variants, water/lava duplicates, empty fluids and sources without a physical liquid block are excluded. Default card/grammar rank is 4, matching the legacy fluid defaults. Source gas/negative-density exclusion requires loader-native fluid attributes: common Minecraft has no portable gaseous/density API, so `setFluidEligibility` lets each loader provide that rule. Forge exposes FluidType lighter-than-air and density; Fabric Transfer exposes lighter-than-air but no corresponding density getter. Existing 1.12 names/configuration keys are not guessed from modern IDs, and old per-fluid sea bans/profiling overrides still require explicit migration/configuration support.

Fluid page names use the native block's translated name. Their poem uses the **values** of original WordData aliases: Transform / Constraint / Flow / native block ID (`Modifier` aliases Transform; `Sea` aliases Flow). Arbitrary native IDs receive the original drawable-word fallback. Runtime glyph rendering is independent of the finite 145-model static catalog.

`ExplorationPages.available(registries)` combines executable static symbols, the actual supported material descriptors, ranked biome pages and eligible fluid pages. Production chest loot functions, library lecterns, archivist offers and booster use pass the actual world registry. Static-only overloads remain for compatibility tests; production does not use them. Existing archivist offers recognize dynamic page ranks, preserving stock/uses rather than repeatedly adding another rank-2 offer.

The rank table is regenerated from original registration expressions, including constructor arguments nested inside `SymbolDummy` and modifier constructors. There are 144 ranked static pages; the unranked static PvPOff exception remains excluded. Material and dummy ranks are not clamped to four. The source rank-normalization algorithm spans the entire available pool and uses source `nextFloat` weighted selection. Boosters retain seven rank-0, four rank-1, four rank-2 and one rank-3-or-higher page. The rare draw includes rank 5. Ordinary treasure stacks retain source rank-dependent maximums; lecterns retain their rare-page rejection-sampling rule.

Creative discovery, page names/tooltips and the browser consume the current registry-backed metadata. The original native IDs remain in NBT through folders, portfolios, desk copying and descriptive books. Generation validates encoded source-fluid identities/states independently; adding a loot choice does not bypass compiler validation or turn catalog-only metadata into an executing handler.

`DynamicPagesSmoke` checks the actual registry's full biome count and source-fluid metadata, the End rank exception, payload copying and disconnected lookup isolation. It invokes the real rank-2 collector sampler and registry-aware booster implementation. Existing exploration/booster smoke helpers were updated to validate native pages rather than assuming every acquired page has an entry in the static catalog. `DynamicPageMetadataTest` checks native identifiers/poems and source rank-5 preservation. Runtime logs must distinguish a vanilla-only server with zero additional source fluids from a modpack actually exercising those fluid choices.
