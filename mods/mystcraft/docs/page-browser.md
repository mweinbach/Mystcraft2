# Classic writing workspace and portable page surfaces

The pinned `GuiWritingDesk` uses a409×186 logical layout: a228-pixel library area, five-pixel separation and original176×166 work panel. It is an automatically arranged30×40 page grid with four visible storage tabs, not an arbitrary free-position canvas. The modern shared screen now uses this source geometry, the original `gui/writingdesk.png` atlas, its58×37 tab fragments and the original page fragment/glyph atlas. All25 persistent library slots remain available through a four-tab viewport that advances one slot at a time and clamps to top indices0..21. Source Up/Down and configured forward/back keys scroll tabs when text input is not focused. Tab labels use the original zero-based number-word glyphs at19 pixels and scale the stored collection/book title below the item slot. Very small GUI-scaled windows can require reducing GUI scale to fit the409-pixel classic workspace.

Search and alphabetical display sorting match localized page names and symbol identifiers without rewriting stored order. Ordered folders retain individual entries. Unordered portfolios group exact-NBT duplicates with physical counts. The all-symbol toggle adds missing catalog symbols as gray zero-count pages: they cannot be selected, taken or printed. It includes the145 static entries and current registry-backed biome/fluid choices; unowned gray entries remain display-only. Displaying a glyph does not grant a page or execute an effect.

Workspace left-click takes an owned page onto the cursor; Shift-left-click takes up to a normal stack of exact matching portfolio pages. Placing cursor pages on the surface/tab moves all that fit, or one with right-click. Right-clicking an owned source, or right-dragging it onto the target strip, invokes server-owned paid writing. A collection target receives one copied payload for one paper and50mB ink. A blank loose page receives the owned symbol/payload for50mB without consuming another paper, preserving unrelated blank-page NBT. A filled loose page is never overwritten. Source stock is retained. Books can also occupy library tabs as read-only owned page sources; taking pages out of a bound book is rejected. The previous explicit paid-copy output remains as a marked modern recovery slot; it is an additional adaptation to the source four-slot work panel.

The target name field supports21 characters for collections/books. Each rename transaction is bound to its exact server target stack; replacing even an equal stack between begin/apply rejects it. Renaming does not mutate page stock. Embedded book targets now use a miniature original-art preview with independent page navigation and a single-click panel link. The server binds the exact menu, desk inventory, target object and full snapshot; changed or replaced targets cannot activate an old view.

Portable folders/portfolios now use the source176×231 layout,132-pixel page workspace,30×40 glyph pages, original176×80 inventory art and source inventory coordinates. They support the same search, grouping, gray catalog view and direct physical take/insert flow. Ordered folder movement also remains available through Alt-drag in unfiltered stored-order view and the explicit one-step controls. Unordered portfolios reject reorder requests. Bulk extraction groups only exact payload matches, preserving distinct nested metadata.

All requests carry bounded menu commands and owned indices, never client page NBT. The server checks reachable desk/open container or exact held collection identity, source/target indices, real stock, capacity and paid resources. New runtime assertions cover paid target writing, blank-page/no-overwrite behavior, source retention, grouped take/tab insertion, stale rename rejection, active tab slots and exact-NBT bulk portable transfers. See [validation.md](validation.md) for the tested artifact scope. These mechanics do not reproduce arbitrary old addon writable interfaces. The explicit paid-copy recovery slot and portable footer controls remain documented modern additions; the screens retain Minecraft1.19 text editing/accessibility rather than copying the old text-input implementation.

The pinned `ItemAgebook.writeSymbol` fills only the first existing blank before visitation; it does not expose arbitrary page insertion/removal on a visited book. The modern desk permits that paid write only on an unallocated descriptive book, consumes50mB ink and no extra paper, and preserves unrelated blank payload metadata. Allocated canonical pages and frozen plans cannot be rewritten. Artifact-specific embedded preview/link and book-writing checks are recorded in [validation.md](validation.md).


## Source widget and scrolling port

Pinned source files are `GuiElementVSlider`, `GuiElementPageSurface`, `GuiElementSurfaceTabs`, `GuiElementScrollablePages` and `GuiElementButtonBase`, under the official1.12/develop commit recorded in [classic-parity.md](classic-parity.md). The source page surface arranges30×40 pages on31×41 pitch. Its slider stores an integer **pixel** offset: each wheel notch moves20 pixels, while dragging anywhere on the track maps `(mouseY-top-11.5)/(height-23)` into the complete pixel range. The fixed15-pixel thumb and original32×32 `gui/scrollbar.png` atlas are preserved. Pages are clipped at the viewport edge, and pointer hit tests use that same pixel offset, including partially visible rows and noninteractive one-pixel gutters. Search/sort/tab changes reset the offset; shrinking results clamp it.

The collection target strip remains source **item-at-a-time** horizontal scrolling, rather than an invented horizontal pixel slider. Its50-pixel height gives33×44 pages on35-pixel pitch, with dark10-pixel left/right overlay regions and one-item wheel advancement. Loose page targets use the source large page preview. Embedded books keep their separate navigation.

Square buttons use the source vanilla `stats_icons.png` slot fragments; nonsquare buttons use the source white/dark-gray bevel and gray fill. Hover highlights and depressed AZ/ALL toggle states follow `GuiElementButtonBase`; pointer actions fire on release inside the button. AZ continues to allow the existing modern stored-order view needed by folder drag reordering. Shader/scissor state is restored after shared page drawing; original glyph composition and resource-pack atlas selection are retained.

Focused verification: `ClassicPageScrollTest` covers pixel wheel movement, partial-row/gutter hit tests, fixed track coordinates, extreme drag clamping, search shrink and revealing a clipped portable final row. Direct javac execution passed all3 tests. The real server `WritingDeskSmoke` now walks past both tab ends, reaches source slot24 and verifies that the final physical inventory viewport is exactly21..24. The final 0.4 suites exercise that viewport on both loaders. Actual Fabric and Forge graphical clients scrolled the 145-page folder, dragged to the final White page and extracted exactly its `GuiOrder:144` payload while preserving earlier pages.
