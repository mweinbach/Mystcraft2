# Black ink and native fluid automation

The pinned reference is Mystcraft-Legacy `9bc8ddc`, specifically ModFluids, BlockFluidInk, ItemInkVial, TileEntityInkMixer, TileEntityDesk and MystcraftEventHandler. The default classic ink is black ink, with tint `0xFF191919`. A filled vial holds one bucket (1000 mB), stacks to sixteen, and yields one glass bottle. It is indivisible: requests below a bucket fail. This port registers shared `black_ink`, `flowing_black_ink`, the liquid block and `black_ink_bucket`.

Flow is shared across loaders: eight levels, water-like movement and tick rate, no infinite-source conversion, and light opacity three. Forge adds a native FluidType and render extensions; Fabric supplies fluid render handlers and a client fog hook. The source fluid art is imported from the pinned Mystcraft resources. The bucket uses the platform's modern bucket container in place of the old Forge universal bucket. Modern bucket pickup returns the correct black ink bucket and removes the source; flowing ink rejects pickup. A glass bottle aimed at ink is denied, preventing vanilla water-bottle creation. Ink is deliberately absent from the global water tag. Forge's `ForgeInkFluidType` provides water-like swimming, drowning, pushing, boating and `WATER` path types without lava solidification or farmland hydration. Fabric registers the same values with the bundled Fluid Physics library (`FabricInkPhysics`), which applies them through MixinExtras operation wrappers so other mods' fluid-query wrappers keep working; direct redirects had failed Tekxit startup alongside Expandability and Spectrum, and the packaged library build needs its own runtime check there. As on Forge, ink is not water: entities in it are not `isInWater` and are not extinguished. A narrowly scoped Fabric camera hook remains for the under-ink view. Ink placement in a warm dimension also has an explicit shared placement path.

The item/tank APIs expose equivalent quantities through Forge capabilities and Fabric Transfer API. Fabric's 81000 droplets per bucket convert exactly to 1000 mB; sub-millibucket tank requests return zero rather than rounding and losing fluid. Both adapters accept the canonical, untagged black ink variant; arbitrary fluid NBT is rejected because the shared inkwell does not store arbitrary fluid metadata.

The writing desk exposes the original 1000 mB inkwell on every side, permitting fractional fills and drains. Forge simulation does not change state. Fabric provisional transactions snapshot the shared quantity, restore it on abort and mark the block dirty only after final commit. Its existing 50 mB copy cost is unchanged. The mixer retains the source's paid boolean basin rather than gaining an invented pipe tank; it accepts exactly one bucket from a native fluid container in its input slot. The desk also accepts native fluid containers, draining only what fits. Both check that the resulting empty or partially emptied container fits their output before changing the real input, tank or basin.

A container adapter always works on a copy of one physical item. Successful machine input then consumes one real input item and stores its corresponding remainder. This avoids the old vial handler's unsafe direct stacked-drain behavior, which could replace a whole supplied stack with a single bottle. Forge rejects unsafe direct stacked vial draining; Fabric's contextual exchange processes a single item transactionally. Existing vial crafting retains its original two black dyes, water and glass bottle cost; no new free-ink recipe is added.

`InkFluidSmoke` checks the installed native vial and bucket handlers, preview preservation of original stack/NBT, indivisible vial rejection, actual source pickup, filled/empty bucket dispenser behavior, native inkwell fractional transactions, adjacent lava remaining lava, and roofed farmland drying beside ink. The native Forge check covers simulate/execute; the Fabric check covers provisional fill/drain, rollback and commit. Source presence is not runtime evidence; the exact tested artifact and loader results belong in the validation logs.

The old Forge `UniversalBucket` constructor explicitly registered `DispenseFluidContainer`. The shared `InkDispensers` adapter therefore registers actual filled-bucket behavior: it fills an empty shared inkwell if a whole bucket fits, otherwise places ink through the bucket's native placement path and retains the empty bucket. Vanilla's empty-bucket dispenser can collect the liquid block through `BucketPickup`. The smoke test invokes the real dispenser tick twice and checks both physical-container transitions and world fluid state. No global empty-bucket behavior is replaced.
