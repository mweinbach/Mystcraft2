# Versioned classic grammar completion

Reference: [Mystcraft-Legacy 9bc8ddc061845df0cd5ea47f4fdef773cff786ae](https://github.com/Mystcraft/Mystcraft-Legacy/tree/9bc8ddc061845df0cd5ea47f4fdef773cff786ae), LGPL-3.0. The new `age.grammar` engine ports `GrammarGenerator`, `GrammarTree`, `WeightedItemSelector` and their collection helpers. It retains the original reverse phrasal parse, shortest-path tie selection, rightmost matching child attachment, insertion ordering, recursive weighted expansion, integer rank-weight construction and zero-total-weight even fallback. Even selection uses `nextFloat`, including singleton choices; replacing it with `nextInt` changes all later choices.

`classic_grammar.tsv` retains the 115 structural productions from `GrammarRules`, the source `SymbolRules` productions attached in symbol registration order, and the 16 source color productions: 226 static productions total. Nullable rank means zero random weight, not an unavailable or forbidden explicit symbol. Empty productions are intentional. Internal grammar names retain original case independently of modern lowercase item identifiers. Material rules enter at the resource's dynamic-binding marker before colors and ordinary symbols, matching `ModSymbols.initialize` calling `ModSymbolsModifiers.initialize` first. Per-descriptor category order is preserved because it affects tied reverse paths.

`ClassicGrammar.forRegistry` adds the ordered built-in material descriptors and actual live biome registry encounter order. Biomes receive rank 1; `minecraft:the_end` receives null rank, matching the original SKY exception. The modern biome identifiers carry registry names rather than fabricating old numeric IDs. The pluggable `DynamicRules` API can supply addon-specific terminal payloads and ordered productions. Original fluid/addon discovery and legacy configuration blacklists are not fully reproduced; a different registry/configuration naturally changes random choices. This is not a promise of identical coordinates or symbol lists across different modpacks.

## Allocation API and persistence

`AgeSymbolCompiler.compile(bookPages, ageSeed, dynamicRules)` returns `Compilation(version, plan, executionPages, symbolSeeds, diagnostics, symbolInstability, explicitEffects)`. `successful()` requires no diagnostics. It validates selected effects through the actual generation and visual compilers; catalog registration does not make an effect executable. A randomly selected unported effect is an explicit allocation failure. The grammar does not remove unavailable rules or secretly renormalize their probabilities.

The book's ordered page payloads remain unchanged. The output is a separate version-1 execution list. Original terminal occurrences carry exact source positions, so duplicate identifiers with different quality or addon payloads retain the correct payload even when randomly inserted occurrences have the same identifier. Generated symbols receive fresh payloads. Blank pages and the linking panel are not runtime symbols.

Legacy `AgeData.getSymbols` uses **two separately constructed `Random(ageSeed)` instances**: one for reverse parsing and one for expansion. `AgeController` then constructs a third `Random(ageSeed)` and consumes one `nextLong()` for every execution symbol in order. The completion API exposes those seeds; execution-mode generation and visual compilers follow the same stream, including dynamic biome/material terminals. The old `parse` entry point remains for pre-existing bounded saved plans. New saved execution lists must be frozen once; an existing generator/visual plan must never be regenerated under the new grammar merely because the mod was updated.

Original written pages are capped at 256. Modern safety limits reject expansion beyond 8,192 terminals or recursion deeper than 128; these bounds replace unbounded resource consumption without altering successful expansions below the bounds. Invalid or unresolved grammar tokens remain diagnostics. Existing unknown page payloads are preserved rather than converted into invented registered effects.

## Costs and ordered modifier semantics

The source executes every terminal, including duplicates. Terrain, biome, weather and lighting controllers use the last registered controller and add 500 instability for each replacement. Costs are not a reason to discard duplicate symbols. The compiler records all source `instabilityModifier(count)` overrides: bright lighting +500; accelerated +1000; explosions -500; meteors -1000; scorched and charged -500 only on their first occurrence; medium/small dummy features +1000/+2000 each; and fortresses, mineshafts, strongholds and villages +100 per occurrence after the third. Other built-in symbol classes inherit source zero cost.

Generation and visual helpers report costs from their actual ordered modifier consumption. A remaining biome costs 100, material 50, and each remaining generic visual modifier value 100 (one stored gradient, not each stop). Sunset modifiers explicitly cost zero. `ModClear` clears pending modifier state and charges 20% of each cleared modifier's dangling amount; ordinary end-of-execution leftovers charge the full amount. Controller and symbol costs plus helper-reported dangling costs form `Compilation.symbolInstability`. Explicit environmental effect counts are kept separately for runtime execution; profiling and automatic instability remain separate systems.

Repeated Star Fissure terminals remain in the execution list. Their feature enablement is idempotent: the original AgeController population loop short-circuits later callbacks after the first success. Other feature registrations preserve their ordered handler lists; unsupported handlers remain explicit diagnostics until their runtime semantics exist. Likewise, original fallback-controller selection via `SymbolManager.findAgeSymbolImplementing` depends on registry/profile ordering and remains an ambiguity for addon grammars that leave mandatory controller groups genuinely empty. Built-in root productions fill the four groups normally.

## Evidence

`ClassicGrammarTest` compares 12 fixed-seed/input expansions byte-for-byte with golden output produced by compiling the pinned **unmodified original** `GrammarGenerator`, `GrammarTree`, `WeightedItemSelector` and `CollectionUtils`. Only Minecraft `ResourceLocation` and the logger were stubbed for that independent oracle. Fixtures include empty input, a fully specified control list with feature dummies, and ordered duplicate weather plus a dangling angle. Both complete token strings and SHA-256 values are retained in `classic-grammar-golden.tsv`. The ported pure Java engine independently matched all 12 vectors using `javac` and `cmp`; centralized JUnit/build execution is performed separately.

Additional tests verify original occurrence provenance, deep-copy isolation, preserved arbitrary nested NBT and independent per-terminal runtime seeds. `GrammarSmoke` validates completion against a real server biome registry, deterministic recompletion, exact dummy costs and rejection of an unavailable registered handler before allocation. These are supplied tests, not a claim that every classic symbol or addon behavior has been ported.
