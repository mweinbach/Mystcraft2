# Dynamic biome and fluid page glyphs

Dynamic pages obtain their four-word poem from the shared `DynamicSymbolPages` metadata API. Biomes retain Nature/Nurture/Encourage plus a stable modern native registry ID. Fluid pages retain the actual source WordData aliases Transform/Constraint/Flow plus native block ID. The namespace-bearing ID replaces unavailable legacy numeric identity; this is an explicit modern adaptation. Known component words use the pinned catalog mappings; arbitrary mod IDs use the source lowercase Java-string-hash/Java-Random word fallback, rather than an unknown whole-symbol question mark.

The client composes the original page background and symbol-component atlas at160×160, paints black using the source alpha blend, and downsamples to128×128 with the original Java2D bilinear operation. Both input images come from the active resource manager, so resource-pack atlas/background changes are honored. Independent reference equations compared49,152 pixels for vanilla biome, modded biome and modded fluid poems with exact ARGB equality. Work evidence: `work/dynamic-page-reference/comparison.log`; permanent unit tests check source positions/blending, deterministic unknown words and input bounds.

Thin client-only mixins route dynamic page ItemRenderer calls through a shared renderer for inventory, hand and world contexts. It applies the current model's transforms (including Forge camera hooks), light/overlay and generated-paper depth. Front/back textures and alpha-silhouette edge spans retain the generated-item shape. Span merging bounds a model to514 faces, even with pathological alpha patterns. Book and workspace pages can use the same direct draw API; static catalog page models remain unchanged.

The render-thread-owned LRU holds at most128 generated textures/meshes. Poems are restricted to four words of at most512 characters each before caching. Eviction releases texture IDs and native image storage; resource reload and client disconnect clear the cache and source images. Original custom addon atlases, per-word colors and seasonal callback renderers are not implemented. This source/image/API evidence does not replace actual loader/mixin and graphical acceptance; consult [validation.md](validation.md) for the tested artifact scope.
