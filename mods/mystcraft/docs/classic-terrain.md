# Versioned classic terrain

Current newly compiled Ages use terrain version 4 and a frozen `ClassicGeneration` plan. See [generation-plan.md](generation-plan.md) for current biome controllers, material queues, geometry, population and structure adapters. The version-one, version-two and version-three descriptions below document retained saved-world compatibility paths; their surface limitations do not describe new version-four normal/amplified Ages. Source implementation and numerical comparisons are distinct from artifact-specific runtime validation.

The original version-one flat, void, Nether and End Ages froze `GeneratorVersion=1`, a `GeneratorSpec`, a resolved `CompiledPlan` and their visual profile in canonical saved Age state. Existing Ages without a version retain the prior `vanilla_v0` generator. The subsequent normal/amplified implementation froze version two as described below. Unknown generation versions fail rather than substitute a different algorithm. Frozen plans prevent future grammar changes from silently rewriting already generated Ages.

Version one ports `SymbolTerrainGenFlat`, `SymbolTerrainGenVoid`, `SymbolTerrainGenNether`, `SymbolTerrainGenEnd` and the density lattice from `TerrainGeneratorBase` in pinned official Mystcraft Legacy commit `9bc8ddc061845df0cd5ea47f4fdef773cff786ae`. Flat ground is 64, sea is 63 and its floor is bedrock at zero. Nether defaults to **stone and water**, sea32, not vanilla Nether materials. End defaults to **stone and air**, sea49, no bedrock. Nether/End density fills y0..127 using the original 5x17x5 lattice and 4x4x8 interpolation. Void contains no base blocks; the separate arrival safety platform remains necessary.

The octave sampler preserves the historical bulk sampler's cached Y gradients. Modern pointwise ImprovedNoise is not equivalent. Independent test-only extraction of the old sampler compared 8,500 values across five seeds and origin, negative, distant and world-edge coordinates with zero error. Extracted official Nether/End density methods compared 17,000 lattice values: maximum absolute floating error 1.14e-13, zero density-sign mismatches. Work evidence: `work/terrain-math/comparison.log` and `density-comparison.log`. Production contains no downloaded reference Minecraft source. Golden density regression vectors are checked into `ClassicDensityTest`.

Explicit remaining adaptations: version-one native biome selection is fixed plains unless a supported single-biome controller specifies another biome; those saved plans do not use the newer classic biome-selection pipeline. Surface finishing uses a deterministic basic biome top/filler adapter, not the old biome noise builders. Nether's bedrock uses a coordinate hash with the same per-height probabilities to avoid classic shared-RNG chunk-order seams. Block modifiers, layers, dense ores, caves, floating-island alterations and Skylands are not part of these terrain slices. Ordinary modern biome decorations remain available through the shared generator pipeline. No silent block-modifier acceptance was added.

`TerrainSmoke.run(server,level)` checks live-registry generator columns, source vertical/default constraints, determinism and frozen saved-data roundtrips without allocating canonical Ages or changing world blocks. See [validation.md](validation.md) for actual runtime and both-loader build results tied to their tested artifacts.

## Version two: normal and amplified

Version-two normal/amplified Ages freeze version two, using the source `SymbolTerrainGenNormal.TerrainGeneratorNormal`, including its amplified positive-height transform, float-based 5x5 parabolic biome blend, asymmetric neighbor weighting, depth-noise shaping and upper fade. Its source also uses the lower128 lattice, rather than modern Minecraft's full world height. Existing version-zero normal/amplified Ages keep their previous vanilla generator. Version-one Ages keep their previous surface adapter. The version-one section above describes those four modes.

Modern biomes lack the old base-height/variation fields. Version two freezes an explicit mapping of modern vanilla biome IDs to corresponding classic profiles. Removed/new biome identities use documented analogous mappings; unknown modded biomes use the plains profile. Native biome **selection** still defaults to fixed plains, and explicit single-biome pages work; this older version does not use the layered biome-provider implementation now available to version-three plans. The density implementation itself accepts spatial profiles and performs the complete source biome blend, including boundaries.

Version two adds the exact classic four-octave simplex surface-noise region and the default classic biome surface state machine: variable thickness, sea-level top/filler choice, deep gravel, temperature-based water/ice, sandstone transition and chunk-seeded surface bedrock. Surface materials use modern biome mappings. Those frozen version-two surfaces do not implement specialized legacy biome overrides (badlands bands/Bryce, mega-taiga podzol, hill noise replacements or swamp pools); new version-four surfaces add them through explicit native-biome mappings. Modern biome temperature and coordinate alignment are adapters, so full block-for-block classic surface parity is not claimed. The basic default state machine is applied in modern natural X/Z coordinates instead of the old primer's transposed surface coordinates.

Independent source extraction compared **51,000** normal/amplified density values across five seeds, four origins and uniform plains, uniform mountains, and mixed plains/mountain/ocean boundaries: **zero error** and zero sign mismatches. Another **3,840** old/new surface simplex values matched exactly. Evidence is `work/terrain-math/normal-comparison.log`; permanent golden boundary vectors are in `ClassicNormalDensityTest`. Runtime smoke now covers all six modes and frozen version1/version2 saved-data roundtrips. Source numerical validation does not replace actual loader runtime or graphical validation.


## Version three: retained biome/material/feature generation

Version three introduced ordered classic biome controllers and complete block-state materials for all six terrain modes. Single/Grid/Tiled and Tiny/Small/Medium/Large/Huge execute the source palette/layer rules; Native explicitly adapts to the modern Overworld climate source. Registry identities and ordered palettes are persisted, including modded biomes. Material queues feed terrain, sea and authored features; controller replacement, dangling parameter costs and assigned symbol seeds follow completed-grammar execution.

The generator executes source-based caves, ravines, spheres, tendrils, floating islands and huge trees, followed by authored lakes, spikes, crystals, obelisks, dense ores and dungeons, with Skylands filtering at the documented modern stage boundaries. Authored native structure controllers select mineshafts, fortresses, strongholds and villages. The source custom scattered feature is the Mystcraft library, not an instruction to enable vanilla temples. See [generation-plan.md](generation-plan.md), [huge-trees.md](huge-trees.md) and [classic-native-structures.md](classic-native-structures.md).

Version-three surface behavior remains frozen. Current adaptations include modern quart biome storage; missing legacy terrain-profile fields for modded biomes; explicit modern identities and deterministic singleton-seed handling for specialized surfaces; modern dungeon contents, ore vein geometry and native structure placement/templates; cross-stage decoration ordering and protected block entities. The old DenseOresEvent extension API has no shared replacement. These are narrower than an unimplemented biome pipeline, and do not imply byte-identical 1.12 chunks. Far-reaching crystal writes now use a persistent deferred queue, replaying only into already loaded FULL chunks instead of expanding world-generation write permissions.

## Version four: current specialized native surfaces

New compilation freezes terrain specification version four without changing the `ClassicGeneration` schema or adding new symbol IDs. Normal/amplified generators add the original native Mesa bands/Bryce/forest plateau algorithms, mega-taiga podzol/coarse dirt, hills/gravelly/wooded threshold rules and swamp pools/lilies. Dispatch uses explicit modern native biome IDs. All previously saved version-zero through version-three generators retain their earlier surface algorithms. Other terrain modes retain their existing surface path.

[Specialized surface implementation](classic-specialized-surfaces.md) records immutable native1.12 reference provenance, mappings, source quirks and independent oracle/golden results. The Bryce previous-world-seed singleton behavior is frozen to deterministic fresh-instance seed0 rather than depending on world visitation history. Modern natural X/Z alignment, quart biomes and temperature remain explicit adapters. Numerical comparisons and source implementation remain distinct from runtime acceptance. The final 0.4 plain-loader suites exercise native version-four surfaces and frozen-version-three contrast; exact artifacts and results are recorded in [validation.md](validation.md). The final Tekxit server suite and fresh-JVM persistence checks also passed with the recorded artifacts.
